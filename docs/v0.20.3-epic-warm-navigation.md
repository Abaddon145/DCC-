# v0.20.3 Epic 连续商品定位（测试版）

基于 v0.20.2 `47092f77c63a19f9d2069bd5cfd4d35be35384d1`，继续 v0.20.0 创作流程版本，不恢复已取消的 UE 原生素材模块，不改 schema、素材、笔记或用户工程。

## 已复现的边界

Epic Games Launcher 20.3.4-0+UE5 已运行时，用户确认栈藏按钮切换另一件已购素材仍不能打开匹配商品。日志同时出现取消中的导航、重复地址 `Already at location` 和 Fab 内页回到 `/plugins/egl`。这些信号只描述导航状态，不足以确定 Epic 内部 WebView 的实现原因，不能当作匹配商品已显示。

针对本机原会话运行诊断技能的人工反馈循环：

- `epic-open-result-hitl.sh`：Windows 调用显示 Replicated Grab System，随后从栈藏选择另一件素材定位失败，结果 `OPEN_RS_VISIBLE=y / APP_SECOND_VISIBLE=n / FAIL`。
- `epic-fab-reset-hitl.sh`：不关闭 Epic，先导航 UE 库，两秒后导航 Ancient Mayan Ruins；原进程保持运行，用户确认商品详情显示，结果 `RECOVERED=y / PASS`。
- 同一会话此前也确认 Mediterranean Coast、Tokyo Stylized Environment 正确显示。不能由此推断任意首次启动、网络条件或 Launcher 版本均已通过。

诊断脚本保存在忽略的 `.tools/`，无原始日志、账户、Cookie 或 Token 提交到 Git。只读取路由阶段及公开商品路径；没有结束进程、删除缓存、变更 Epic 设置或执行安装。

## 最小修复

共享 `open_fab_in_epic` 入口每次先离开 Fab，后台交接两秒后打开保存的商品 UUID。同一时间只接收一次交接，避免不同素材或不同弹窗互相取消请求；不会排队自动执行已经关闭窗口的重复点击。

等待不持有素材库锁。两个导航阶段均校验当前库、素材仍未删除且 Fab 来源与保存 UUID 一致，切库或来源变化后不再派发旧商品地址。工程和官方支持版本的既有校验保持不变。

弹窗显示交接中状态并禁用定位、重试按钮；只返回“请求已发送”，不声称商品已显示或已经下载、安装。

两秒是本次实机会话验证过的交接间隔，不是 Epic 官方就绪回调。首次启动或加载较慢时仍可能需要等 Epic 就绪后重试；未增加读取登录状态、自动重启、账号接管或持续自动重试功能。Epic 官方安装流程仍需用户在商品页确认工程和版本，见 [官方文档](https://dev.epicgames.com/documentation/fab/exporting-assets-from-fab-in-launcher)。

## 回归与交付

共享导航顺序的 Rust 用例先在单阶段实现上运行失败，再修复后通过，包含 A → B → B 重复请求。额外检查交接失败、素材在等待中删除及首阶段调用失败时不再发送商品请求。前端等待状态用例也先失败再通过，覆盖交接期间禁用按钮、不重复提交和不虚报商品已打开。

自动化测试只能约束调用顺序和应用保护；本机恢复流程经过人工视觉确认，新安装包内的完整按钮流程仍须按下方步骤复测。

完整回归：前端 51 文件、238 项通过；Rust 191 项通过、2 项既有手动/大型数据用例忽略；TypeScript/Vite 生产构建、Rust 格式检查和源码凭据模式扫描（239 文件、0 命中）通过。未增加依赖。既有生产大分块及未使用函数/链接器提示未在本补丁中扩展处理。

## 安装包验收

1. 保存当前编辑，关闭栈藏后手动安装 v0.20.3；无需关闭 Epic。旧包与用户数据保留。
2. 从栈藏连续定位至少三件不同的已购素材，每次核对商品名，不以探索首页或日志 `Navigation Complete` 作为成功。
3. 关闭 Epic 中商品详情回到探索首页，再从栈藏定位另一件素材；重复定位同一素材也应能重新打开。
4. 交接时按钮不可重复提交；切库、素材删除或 Fab 来源变化后旧商品不再派发。
5. 冷启动 Epic 和较慢网络场景需额外复测。只有用户在 Epic 商品页确认安装才会开始下载，测试不主动触发下载。

验收前继续保留草稿 PR，不 squash 合并、不创建正式 Release；安装产物和本机诊断数据不提交到源码。
