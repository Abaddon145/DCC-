# v0.19.1 浏览器扩展修复

## 已确认的根因

- 弹窗只有 `body.width:420px`，同时受 `max-width:100vw` 限制；浏览器初始化窄视口时无法正常扩宽，中文折成竖排。改为根元素固定 440px/min-width、内容滚动、底部操作固定。
- Windows 实机检查发现 Edge/Chrome 没有 `com.stackdcc.capture` 的 HKCU 注册项。因此打开软件、保存都在 Native Messaging 建连处失败。安装扩展本身不等于登记本机通信桥。
- 原生连接发送失败后仍保留断开的 port；后续点击继续复用失效连接。新增回归已验证修复后重新建立连接，旧连接的迟到断开事件不会清掉新连接。
- 建连失败的采集没有保留选中项、没有打开修复提示。现在保留待保存内容，打开面板；连接失败自动展开说明，并提供复制 ID、重新检查连接。打开软件成功后刷新连接状态。

首次登记仍需要用户明确连接扩展 ID；不新增全来源授权、外部 URI 协议或本地 HTTP 监听。软件升级启动会刷新**已登记**通信桥的 EXE 路径。新增受同一 ID 验证约束的 `--register-browser-capture-host <extension-id>` 用于本机安装修复，不接收任意可执行文件路径。

## 验证

- `npm test -- --maxWorkers=2`：49 个文件、207 项通过。
- `cargo test --offline --lib -- --test-threads=1`：168 项通过、2 项忽略；新增连接配置路径更新/来源保留/非法 ID 和路径拒绝检查。
- 修复前 popup 布局/连接提示、失效 port 重连、采集选择保留回归均失败，修复后通过。
- TypeScript、生产构建、扩展 JS 语法、Rust 格式和中文 x64 NSIS 打包通过。原有大 chunk、未使用函数和 linker 提示仍存在。
- 隔离环境中的真实 release EXE + Unicode `.cmd`：PNG 字节、分帧、来源参数拒绝、排队状态和 EOF 检查通过。
- 经授权更新现有软件安装和原扩展目录、登记当前已安装 ID；原扩展文件备份保留。通过已安装 EXE 和真实已登记通信桥发送 **hello**，验证能后台启动/连接当前素材库且采集启用；未向用户素材库提交任何测试媒体。
- 浏览器 UI 自动化授权超时，未代替用户重新加载插件。实际网页右键保存、截图、页面权限与打开主窗口仍需浏览器重新加载后的实机验收，不能用 hello 检查代替。
