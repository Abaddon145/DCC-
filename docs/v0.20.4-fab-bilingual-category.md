# v0.20.4 Fab 双语、分类与定位修复（测试版）

继续 v0.20.0 创作流程版本，不升级数据库 schema。更新提交到私有仓库 `Abaddon145/DCC-` 的现有草稿 PR。

## 双语保存与分类

用户报告单条 Fab 读取后保存没有中文。只读核对发现，本机 `fabAutoTranslate` 为关闭，保存记录的中文名称、描述、许可均为空；原界面仍承诺保存时补齐，而且编辑已有素材的保存分支不会补译。

单条与批量导入现在读取、显示和持久化同一个自动补译开关。开关开启后，新建素材及主动重新读取 Fab 的已有素材保存时补齐缺失字段；普通编辑不增加在线请求。中文标题已有但描述缺失也会准确显示待补译。服务失败保留原文和已成功字段，不覆盖用户内容。

保存窗口显示实际分类、缺失字段和原因，提供按已保存素材 ID 重试。关闭窗口后，单条结果仍在任务中心；重启不会自动重发在线请求。任务记录写入失败会明确提示“素材已保存”，避免引导重复创建。

单条与批量分类都来自 Fab 的 `suggestedCategoryPath`，由后端同一官方映射生成，并通过同一个数据库保存事务创建或复用分类。主动重新读取 Fab 的未分类旧条目也会保留建议；用户手选分类优先。取消编辑不会创建分类，不自动整理历史素材。

本机按已确认的选择开启自动补译，修改前设置副本留在忽略目录 `.tools/user-settings-before-v0.20.4/`。没有请求真实翻译服务或修改已有素材。

## Epic 定位与操作反馈

正常定位只发送当前商品地址，不经过 UE 库、不等待两秒。只有用户点击“定位无响应？恢复定位”才使用此前实机会话确认过的 UE 库交接。共享的并发保护、库身份、素材删除和保存商品 ID 校验保留。

详情提供快速定位，无需工程及版本选择；原“通过 Epic 添加到 UE 工程”保留真实工程版本和 Fab 官方支持版本检查。打开商品后的下载、版本和目标工程仍由 Epic 确认，应用只声明定位请求已发送。

关闭未保存素材编辑需确认。导入处理中不允许替换文件、改列映射或自动补译设置，异步结果在关闭或切库后失效。导入、补译和任务中心逐行结果按 100 条分页，不再截断到前 500 条。

## 安装后核对

1. 保存编辑并关闭栈藏，安装本次测试包，继续使用原素材库。
2. 读取一件未录入 Fab 商品，确认自动补译已勾选，保存后核对中文、英文和分类。未创建的分类应在保存后出现。
3. 对已有缺失中文的素材，可从详情补齐，或编辑后重新读取 Fab 再保存。已有译文与手选分类应保留；服务失败可在任务中心查看原因并手动重试。
4. 保持 Epic 运行，连续定位三件不同素材，正常操作不应经过 UE 库。未切换时手动使用恢复定位，再核对商品名称。
