# v0.20.5 DeepSeek 分段补译修复（测试版）

延续 v0.20.0 创作流程版本。只修正现有共享翻译管线，不新增依赖、模块或数据库迁移，不改变 Epic 定位流程。

## 问题与复现

Ready Map Vol 2 保存后的截图显示中文描述、中文标签待补译，原因都是“DeepSeek 译文数量不匹配或为空，未应用或缓存”。自动补译已经执行，并非自动翻译开关问题。截图未提供原始服务响应，不能断言它实际省略了哪一段。

用本地模拟 DeepSeek 响应触发真实解析和翻译会话：两段输入返回一段合并译文。修复前 `malformed_deepseek_batch_recovers_without_poisoning_other_fields` 稳定失败，出现截图中的同一报错，运行耗时 0.03 秒。源代码把译文格式问题归为请求配置错误，直接返回并停用该服务 60 秒；上层原有分段修复因此无法执行，后续标签也被同一错误阻断。

另外，术语保护后的连接符、括号、数字和标点仍会成为待翻译片段。它们现在在本地保留，不要求服务提供无意义的译文。DeepSeek 官方说明也指出 JSON 模式可能返回空内容，输出可能被长度限制截断；因此仍须校验内容，不能把 JSON 格式有效当成翻译成功。[官方 JSON Output 说明](https://api-docs.deepseek.com/zh-cn/guides/json_mode/)。

## 修复边界

- 译文条数、类型、JSON 内容、空译文或长度截断异常与鉴权、额度、请求参数错误区分。
- 错误的多段响应不写素材或缓存；在共享翻译会话中缩小输入再请求，每批最多四次分拆，正常响应仍要求严格对应输入条数。
- 格式异常不再停用整个服务。无法修复的字段保留待补译，其他字段可继续；备用服务仍遵守现有自动切换设置，不绕过鉴权错误或本机额度上限。
- 每次请求及分拆后的请求先检查共享月度额度，失败响应的已报告用量也准确结算；未报告用量仍保留保守预留。
- 内容过滤和未知停止原因不自动分拆规避；缺少用量也不会反复请求。
- 手动翻译、Fab 单条保存、Fab 批量导入、补齐双语共用这套处理。删除上层无法到达的重复分段修复，保留中文专业术语、URL、版本和代码标识符保护。
- 有效旧缓存继续复用，不清空缓存、不覆盖用户已有字段；源码、日志和预览不包含凭据或完整在线请求。
- 失败提示区分“应返回几段、实际几段”和“第几段为空”；达到修复上限后提示手动重试，不伪装双语已完成。

## 安装后核对

1. 保存编辑并关闭栈藏，安装 v0.20.5 测试包，继续使用原素材库。
2. 对 Ready Map Vol 2 使用“重试缺失译文”，核对中文描述、标签已补齐，同时原英文、现有中文标题、分类和图片保持不变。无需删除并重新录入。
3. 再核对一件未录入 Fab 商品的读取、保存以及批量“补齐双语”。服务仍失败时，提供新的具体错误文字；本补丁不保证外部服务永不返回异常，也不规避余额不足或无效凭据。

真实账户翻译、安装后行为仍需实机验收；验收前保持现有草稿 PR，不自动安装、不合并或发布正式 Release。
