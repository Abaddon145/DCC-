## 来源预检的一致性视图

预检原先对来源逐条查询但没有覆盖全程的读取事务。隔离 WAL 测试用视图与 SQLite 测试函数在读取系列时让独立连接提交新进度：修复前预检返回提交后的 21000 ms，而在预检开始时是 11000 ms。加入来源读取事务后，预检一致返回 11000 ms，另一个连接的 21000 ms 提交仍存在；失败时来源和目标事务均释放。测试中的视图仅为确定性控制并发时机，不是对真实来源结构的兼容承诺。

Windows Rust 全量 699 通过、0 失败、2 忽略，日志 `release-artifacts/yingliu-merge/course-preview-snapshot-rust-full.log`；迁入专项 Rust 115 通过、前端 19 通过，日志 `release-artifacts/yingliu-merge/migration-qa-tC7YhK/`。来源连接若已处于事务中会失败闭合。来源和目标各自在自己的读取事务内一致，不代表两库之间是同一个原子快照；后续提交仍需复核来源和目标状态。本次不开放真实源读取或实施数据迁移。

## 预检字段的来源和目标指纹

在各自读取事务内，以带版本域的结构化 JSON 和 SHA-256 生成两枚独立指纹。来源指纹覆盖当前预检的系列、课程标识、标题、顺序和进度；目标指纹覆盖来源课程标识、所请求的媒体 ID、是否解析成功、已有目标课程、进度和系列关系。现在可以区分未绑定与绑定了不可用媒体。目标进度或系列修订变化仅改变目标指纹，来源进度变化仅改变来源指纹；重复预检的结果稳定。

Windows Rust 全量 700 通过、0 失败、2 忽略，日志 `release-artifacts/yingliu-merge/course-preview-fingerprint-rust-full.log`；迁入专项 Rust 116 通过、前端 19 通过，日志 `release-artifacts/yingliu-merge/migration-qa-a62Fmj/`。先运行的指纹测试因缺少指纹按预期失败，补充实现后通过。

指纹只覆盖本预检已读取的字段，不证明数据库文件、WAL、媒体原件或其他未展示字段没有变化，也不绑定来源 profile、素材库根或会话。它们不是授权或提交许可；生产提交仍需重新读取并比较对应字段、单独核验文件身份与授权范围，并以持久操作记录保护执行。本步没有实现提交或迁入入口。

## 内部预检复核

`recheck_preview` 使用给定的来源快照、目标连接及媒体绑定重新预检；来源或目标字段指纹不同则分别返回重新预检错误。合成测试先验证未实现时失败，再验证未变化可复核、来源进度变化、目标系列修订变化和未解析媒体绑定变化均被拒绝；无效来源拒绝并释放事务，目标进度未改动。

Windows Rust 全量 701 通过、0 失败、2 忽略，日志 `release-artifacts/yingliu-merge/course-preview-recheck-rust-full.log`；迁入专项 Rust 117 通过、前端 19 通过，日志 `release-artifacts/yingliu-merge/migration-qa-pgiYGF/`。

复核不开放任何外部命令，不检查来源或媒体文件身份、来源授权、目标库会话和预检令牌的可信归属。它在返回前结束读取事务，返回后数据仍可变化；不能直接用作迁入提交的原子保护。生产实现必须在受保护的提交流程中重新核对，并独立解决授权、文件身份、恢复和来源数据一致性。

## 来源课程与进度元数据

依据映流 schema 8 输入协议，预检额外保留系列说明、课程条目的可空时长，以及来源进度的最后播放时间、更新时间和会话序号。没有来源进度时元数据保持缺失；课程时长为 NULL 时保持未知，负时长失败闭合。来源序号只作为来源数据保留，不当作目标修订号。来源字段指纹使用 v2 域，覆盖这些新增值；目标指纹域不变。
