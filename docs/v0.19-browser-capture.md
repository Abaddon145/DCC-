# v0.19 浏览器采集与收件箱

## 确认的边界

不新建与创作项目重复的 UE5 工作台。增加默认启用的采集收件箱，复用独立媒体库、项目、笔记和参考板；仅用户主动采集。首版 Edge/Chrome，本地扩展安装，不承诺商店审核或任意平台视频下载。

## 流程

浏览器 Native Messaging → UUID 暂存目录 → 当前库 UUID 校验 → 持久后台任务 → 现有媒体导入/FFmpeg → 收件箱记录与来源元数据。新媒体、来源记录及项目关联在同一个 SQLite 事务内提交，导入失败清理新媒体暂存，不写半成品。

schema v18 增加 `browser_captures`（来源、媒体或链接种类、可选媒体 ID/项目、处理和整理状态）。既有 schema v17 笔记结构不变。采集记录不级联删除媒体；媒体回收站/永久删除后收件箱显示不可用。库内数据通过现有数据库和托管媒体备份机制保存；浏览器的未完成全局队列不包含在素材库备份。

通信桥只接受登记的扩展来源。帧最大 512 KB、每块 128 KB、图片 25 MB/2500 万像素、视频 512 MB、待处理最多 500 项、单批最多 100 项。真实文件由已有解码器/FFprobe 再验证。没有监听端口或接收任意磁盘路径的接口。

运行锁使用 Rust 标准库 OS 文件锁（Rust 1.89+）；进程退出/崩溃后自动释放。浏览器后台启动不主动显示主窗口，显式“打开栈藏”才显示收件箱。Rust 后台定时接收避免 WebView 最小化后计时器节流；库维护、恢复中断和模块禁用时停止接收新导入。

扩展不保存账号凭据，图片读取由浏览器在明确授权域名上尝试；视频请求不带登录凭据。失败可保存页面链接及可读取封面，结果不会误称视频文件已保存。图片防盗链、跨域跳转和不支持格式需要截图替代。

资源下载 URL 只留在浏览器，不进入通信桥或库备份。来源 URL 移除片段及常见登录、Token、签名查询参数，Rust 再次拒绝含这些参数的元数据。不能保证识别网站自定义命名的敏感参数，请勿主动采集包含私密信息的页面。

任务提交与切库在同一素材库锁内校验，原库的待处理项目不会误写到新库。收件箱整理、共享详情编辑和项目/参考板关联同样绑定 UUID；模块停用后隐藏入口。媒体库继续显示为可折叠组，组的位置按第一项媒体模块排序，收件箱可移到组前或组后。

超长文件夹/项目选择列表按序列化字节限额截断并提示，可先保存到收件箱，再在应用里整理全部目标；原始数据不受截断影响。
