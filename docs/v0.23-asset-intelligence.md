# v0.23.0 Asset Intelligence Layer — 资产智能层体验版

当前交付为本地中文 Windows x64 测试版。未推送、合并或发布 GitHub Release；真实 AI 模型、Epic、超大文件与干净环境安装仍需人工验收。安装前请导出素材库备份并关闭旧版。

## 新增模块与使用方式

1. 在素材库切换“全部资产”，可以创建 Prompt、登记 Shot，并按类型、来源和项目筛选。普通素材和四类媒体的原入口继续保留。
2. 统一详情固定十个页签：基础信息、文件、Metadata、标签、来源、版本、关系、AI 分析、Prompt、项目。方向键、Home/End 可切换；外部点击与 Escape 关闭前保护未保存的 Prompt/Shot 内容。
3. 关系支持 inspired_by、generated_from、derived_from、used_in、reference_of、variant_of、related_to。前五种保留方向，后两种反向添加复用同一关系；禁止自连和跨库端点。局部图每页最多 80 个邻居，不读取整库。
4. AI 分析先显示文字和将发送的图片，确认后才进入现有任务中心。图片缩至最长边 1024 像素、每张最多 256 KiB；视频仅抽取 10%/35%/65%/90% 四个时点，不上传整段视频。模型、音频、Prompt、Shot 只整理所确认的文字。
5. 复用当前 DeepSeek 凭据、月度额度、请求取消和任务记录；缓存按资产身份、资料指纹、模型、模式和格式版本区分。资料替换、修改、切库或取消后，过期任务不能应用迟到结果。主动重新分析需再次确认。
6. AI 描述、关键词、场景、风格、镜头、光照与情绪独立保存；不覆盖原描述或许可。建议标签由用户勾选，追加到当前标签集合，不以旧快照替换其他操作新增的标签。
7. 离线搜索覆盖名称、用户描述、标签、已保存 AI 描述/关键词、来源 URL/作者与项目，组合筛选保持 AND。查询中的引号、百分号和下划线按普通文字处理；后端单页最多 200 项。
8. Prompt 是无文件的原生资产，记录标题、说明、正文、模型和 JSON 对象参数。支持复制正文、标签、项目、输入/输出关系及回收站；保存不执行生成。修订冲突保留草稿，不强行覆盖其他修改。
9. 项目中的已有镜头可以登记 Shot；也可选择项目/场景创建镜头并登记。ACT、镜头编号和四列状态只属于该 Shot。镜头名称、说明、帧范围、分辨率和帧率仍由原项目镜头负责，旧入口修改名称/说明会同步更新 Shot 修订。
10. 删除项目/镜头只解除 Shot 绑定，保留创作记录、关系及被引用的素材。删除 Shot 不删除原镜头；软删除和恢复沿用现有回收站。
11. Embedding 仅提供有限数值的本地存储接口（1–4096 维），未配置时语义检索明确返回“未配置语义检索”。没有新增向量数据库、自动识别或隐式联网。

## 映流及既有能力

本阶段没有再次迁移映流，也未修改 video_downloader。下载中心、文件处理、普通素材/Fab 双语与分类、参考板、知识库、项目、模型预览与备用翻译沿用原模块。新增 AI 分析不由导入自动触发，不与下载队列另建一套任务系统。

实现沿用现有 Rust/React、SQLite、图片处理和共享服务，没有新增依赖、DCC 插件、聊天窗口、UE 原生素材模块或生成 API。UI 只扩展统一详情和项目登记入口，沿用主题、焦点提示和减弱动效设置。

## 数据库变化与兼容

schema 21→22，新增：

- asset_relations：有向/对称关系、端点外键和去重约束。
- asset_ai_analysis：已校验结果、模型、模式、资料指纹、格式版本与实际 Token。
- asset_embeddings：按资产与模型记录向量和维度。
- asset_entities：Prompt/Shot 标题、说明、修订及软删除。
- prompts、shots：各类型附加字段；Shot 对旧 project_units 的唯一绑定。
- asset_entity_tags、asset_entity_projects：复用现有词库和项目的关系。

仅重建 asset_core 的来源约束以接纳第三种文本来源，保留原核心 UUID、来源 ID、时间、文件/版本引用及已有清理触发器。创建表、替换注册表、登记旧来源和 schema 更新处于同一事务；成功和失败都恢复外键开关。升级不移动或重新导入旧文件。

Prompt 上限：正文 100,000 字、标题/模型 200 字、说明 10,000 字、JSON 参数对象 16 KiB。Shot ACT/编号各 80 字，状态固定为待办/进行中/待检查/完成；新镜头与文本资产同一事务创建。

备份容器格式不改，数据库自动包含全部新关系、分析与文本实体。媒体仍在原托管路径；密钥、在线用量与临时任务缓存不进入素材库备份。旧备份打开后按原迁移入口升级；直接使用旧版本读取新 schema 不属于回退方案，应恢复升级前备份。

## 类型化接口

新命令均包含 expectedLibraryId，后台任务绑定准备资料时的素材库：

- create_asset_relation / delete_asset_relation / get_asset_graph
- prepare_asset_analysis / get_asset_analysis / apply_asset_analysis_tags
- upsert_prompt_asset / get_prompt_asset / trash_text_assets
- upsert_shot_asset / get_shot_asset / list_project_shot_assets

沿用 search_core_assets、get_core_asset、标签、来源、版本和项目接口。get_asset_analysis 增加可选 analysisId，明确读取所复用的旧缓存结果，不误显示“最新一条”。

## 测试与性能记录

阶段 1–6 各自执行 RED→GREEN 和整套回归；新增用例覆盖方向与重复、端点归属、缓存确认、原件替换、视频抽帧、取消与迟到响应、标签并发追加、特殊字符检索、Prompt 冲突和软删除、Shot 事务及旧入口同步。CI 使用本地模拟响应，不调用真实 DeepSeek 账户。

最终闭环数据库测试建立 image → Prompt → video → Shot，保存分析、关系和 Prompt 软删除后导出备份；删除当前库关系/分析再恢复，核对 UUID、文件引用、分析、Shot 绑定、回收站状态和外键。测试视频是数据库文件引用 fixture，不把它称为真实视频解码验收。

10,001 项/10,000 个中心关系的本机实测：200 条检索约 **54.55 ms**，80 个邻居查询约 **25.37 ms**。验证总数、分页和截断，没有脆弱的固定 CI 时间阈值；这不是所有用户机器的性能承诺。

完整回归：前端 **309/309（64 文件）**；Rust **328 通过、2 项原有忽略**，主程序/文档测试退出 0；生产构建退出 0。cargo fmt --check、git diff --check 均通过；源码凭据扫描 **336 文件、0 发现**。独立审阅与安装包结果在最后验收后补记。

两个既有忽略项仍需人工数据/网络条件：大型笔记性能、用户 Markdown 远程图片；不计入通过数量。生产构建仍有原有大 chunk 提示（主包约 1,496 kB，知识库约 611 kB）；本阶段未增加依赖，尚未进行整站代码拆分。Rust 保留 MSVC 链接信息；仅预留的 Embedding/语义接口在 Release 中有未使用提示，不属于构建失败。
