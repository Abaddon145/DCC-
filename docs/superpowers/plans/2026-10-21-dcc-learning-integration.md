### 后续共享接口预检

| 生产者 → 消费者 | 最新结构及适配要求 |
| --- | --- |
| `asset_core` → 媒体交接 | 核心资产 ID、旧素材 ID、`media_entries.id` 是不同身份；`kind=media` 只能使用媒体条目 ID，先经 `asset::repository::origin` 转换，不把所有资产当视频。 |
| 启动入口 → 实体导航 | 已有 `browser_capture::application_lock`、`request_open` 和 3 秒 pump；只唤起窗口，不传目标实体。后续按确认协议扩展独立请求收件逻辑，保留现有锁及采集链路。 |
| 库作用域 → 异步任务/回执 | 使用 `with_library_if_id` / `with_library_mut_if_id` 和任务维护屏障；长 hash 在锁外执行、发布前复核身份及源件。旧响应不可写入新库。 |
| 接收事务 → 笔记/参考板 | 现有笔记引用仅有 note/asset/media/project；外部课程/时间码不能冒充本地 ID。附件复用 `knowledge_files`、参考板快照复用 `reference_boards`。明确新增外部引用表达后才动迁移。 |
| 项目关联 → 学习资料 | 复用 `projects`、`project_media_entries`、`ProjectHub`；新增关联记录，不再建项目系统，不复用本地笔记引用来存外部笔记全文。 |
| 备份恢复 → 回执去重 | SQLite 进入整库备份；运行时目录不进入备份。跨库恢复保留目标库 UUID 而实体 UUID 保留，关联必须有完整库作用域；配对状态不得因备份恢复直接获得机器授权。 |
