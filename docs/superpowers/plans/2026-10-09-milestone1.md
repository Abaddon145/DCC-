# 栈藏里程碑 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 v0.20.6 完成 A1 → A2 → A5 → A3 → A4，改善导入反馈、定位可靠性、费用确认和升级前保护。

**Architecture:** 复用 Fab 警告、共享翻译管线、SQLite 快照和原子设置写入。翻译增加只读投影，升级备份在迁移前运行；保留既有 schema、额度保护与完整备份流程，不引入通用框架。

**Tech Stack:** Windows x64、Tauri 2、Rust、rusqlite、React 19、TypeScript、Vitest；全部使用已安装依赖。

**Spec:** `docs/superpowers/specs/2026-10-09-milestone1-design.md`，已确认；同时遵守用户原任务书。

## Global Constraints

- 顺序固定为 A1 → A2 → A5 → A3 → A4，各任务独立测试、各一个中文提交，格式为 `A1：简述`。
- 不新增 Rust/npm 依赖，不升级数据库 schema，不改变历史素材或已有任务记录文件格式。
- 所有新设置字段具有 serde 默认值，兼容旧设置文件。
- 不修改版本号，不打包安装程序，不合并 PR，不创建正式 Release；不提交本机设置、凭据、日志或安装产物。
- 不读取 Epic 账号、密码、Cookie 或 Token，不自动下载、安装素材；只提示“请求已发送”，不声称商品已打开。
- 不放宽 Fab HTTP 来源、重定向、大小限制，不放宽 `registered_listing` 校验，不改变 Epic 导航互斥和恢复定位的两秒交接。
- 不修改在线翻译实际额度检查、预留、结算或降级策略；估算只读，不联网、不写用量或缓存。
- 不顺手拆分或重构 `commands.rs`，复用现有逻辑和样式变量，用户提示使用简体中文。

## Review Focus

- 手动读取 Fab 后保存绕过后端二次读取：格式警告仍应出现在保存结果，取消编辑不得写入素材数据。
- Fab 只粘贴网址、尚未读取：不能以空表单的估算冒充完整商品补译费用。
- 关闭窗口、换素材、换库或快速重复点击：旧估算不得授权新输入，等待期间不得重复发送。
- 恢复中断标记仍存在：升级保护不得迁移、覆盖数据库或绕过现有维护模式。
- 同一库标识的复制库、备份目录链接或伪装成自动文件的手动备份：逐库判断不能漏保护，清理只能删除登记且路径验证通过的自有成功快照。

## 文件与接口约定

保持 `commands.rs` 原结构；只新增相关命令及测试。A1 的 `SingleAssetSaveOptions.formatWarning` 被 A3 继续保留；A3 新增的 `skipAutoTranslation` 不替代现有 `autoTranslate` 开关。A4 不改变 A3 共享服务统计或现有定时完整备份。

执行方式建议 **Native**：由当前会话逐项实施，最终一次独立只读审查。三个任务共用保存、类型和接口文件，连续实施可减少重复阅读；用户在审阅本计划时选择执行方式。

## Task 5：A4 升级前元数据库快照

**Files:** 新建 `src-tauri/src/upgrade_backup.rs`；修改 `state.rs`、`lib.rs`、`src/types.ts`、`src/lib/api.ts`、`src/components/ReliabilitySettings.tsx`；新建 `src/components/ReliabilitySettings.test.tsx`；Rust 测试放在新模块和 state 现有测试模块。

**Interfaces:**

- `UpgradeBackupRecord`：`last_success_app_version: String`、`last_attempt_at: Option<String>`、`result: Option<String>`、`message: Option<String>`、`snapshots: Vec<UpgradeBackupFile>`，全部兼容缺省值。
- `UpgradeBackupFile`：`name: String`、`created_at: String`；仅登记成功、校验过的本功能快照，不接受前端提供文件名。
- `UpgradeBackupStatus`：`keep: i64`、`last_attempt_at: Option<String>`、`result: Option<String>`、`message: Option<String>`、`backup_directory: String`。
- `pub(crate) fn run_upgrade_backup(base_dir: &Path, version: &str, keep: usize, record: &mut UpgradeBackupRecord) -> Result<UpgradeBackupStatus, String>`；逐库键是规范化绝对路径的 SHA-256，Windows 大小写归一，不只依赖可复制的库 UUID。
- Tauri `get_upgrade_backup_status(state: State<AppState>, library_id: String) -> Result<UpgradeBackupStatus, String>` 和 `save_upgrade_backup_keep(state: State<AppState>, library_id: String, keep: i64) -> Result<UpgradeBackupStatus, String>`；核对当前库，不开放任意备份路径输入。
- 对应 `AppState::upgrade_backup_status(&self, library_id: &str) -> Result<UpgradeBackupStatus, String>` 和 `AppState::save_upgrade_backup_keep(&self, library_id: &str, keep: i64) -> Result<UpgradeBackupStatus, String>`，设置与逐库记录仅由 state 访问。

- [ ] **先写启动入口失败测试。** 在 state 现有临时库测试中增加 `upgrade_backup_precedes_migrations`，调用当前打开流程后断言存在保留旧 schema 值的快照；还没有新模块时，测试应明确失败于快照不存在，而非导入错误。
- [ ] **运行 RED。** `cargo test --locked --lib upgrade_backup`，确认当前打开流程缺少保护行为。
- [ ] **增加核心检查。** `upgrade_backup_same_version_skips`、`upgrade_backup_new_version_once`、`upgrade_backup_integrity_failure_keeps_file_and_version`、`upgrade_backup_keep_only_removes_registered_oldest`。断言只读快照 `integrity_check == "ok"`；成功后版本记录才变化，失败文件不删除；后续每个新增分支继续先写失败断言。
