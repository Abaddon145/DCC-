# DCC v0.22 Asset Core 2.0：兼容式升级设计

## 1. 已确认的目标与边界

依据用户提供的《DCC v0.22 Asset Core 2.0》任务书，并采用用户确认的方案 A：保留旧数据与入口，兼容式升级。

目标是让一个逻辑资产汇集文件、缩略图、元数据、标签、来源、版本、关联项目、处理记录和已有知识关联，而不是把每个物理文件视为彼此无关的素材。

保留 Fab、双语翻译、普通素材、四个独立媒体库、创作项目、知识库、参考板、回收站、备份和 v0.21 下载中心。不开发 AI 分析、自动语义标签、向量搜索、Prompt 系统、剪辑、自动镜头识别或 UE 完整资产浏览。不重做整体 UI，不修改映流仓库。

当前工作区有尚未提交的 v0.21.1 Fab 定位与下载界面修复。不得覆盖、丢弃或混入无法区分的提交。

## 2. 当前实现与任务书的兼容差异

| 任务书概念 | 当前实现 | 本次处理 |
|---|---|---|
| assets | 已有 Fab/网盘素材表、双语表及回收站字段 | 不替换、不重建；通过统一核心连接 |
| Asset Files | media_files、images、asset_media 已托管多类文件 | 登记已有文件，不复制文件内容 |
| Metadata | 已有尺寸、时长；media_engine/probe.rs 可读编码、FPS | 复用解析，补充统一元数据记录 |
| Tags | tags、localized_tags 及素材/媒体关系已存在 | 复用共享词库与双语关系，不另建同名词库 |
| Sources | 普通素材 source_url、媒体 source_url、media_sources | 保留原值，统一查询并支持新增来源 |
| Projects | project_assets、project_media_entries 已存在 | 通过核心接口读写现有关联 |
| Hash | 主文件已有 SHA-256 唯一索引 | 延续去重，不删除索引以制造重复文件 |
| BackgroundTask | 现有 TaskRequest / LibraryTask 队列 | 增加请求种类，不另建平行任务系统 |

应用版本 v0.22.0 与数据库 schema 编号是不同概念。当前 schema 为 20，本次迁移编号为 21，不能把数据库版本直接设置为应用版本 22。

## 3. 统一身份与数据归属

新增 Rust `src-tauri/src/asset/` 深模块，按任务书拆分 models、repository、service、scanner、metadata；它对前端提供统一资产接口，隐藏旧表差异。

增加 `asset_core` 注册表，不占用已有 `assets` 名称。每条核心记录拥有稳定 UUID，并且恰好连接一个旧普通素材或媒体条目；两个来源 ID 各自唯一。旧素材 ID、媒体 ID、笔记引用、项目关系、协议 URL 和文件路径保持不变。

名称、描述、收藏、删除状态等已有字段仍由原表负责。核心查询通过适配器读取，不复制出第二份可以互相覆盖的名称或描述。旧入口编辑内容后，统一资产浏览立即读取最新值。

旧普通素材与已经关联它的独立媒体仍是不同资产身份，以保留媒体可独立存在的既有规则；关联显示为相关资产，不在升级时自动合并。

## 4. 增量 schema 与生命周期

在一次迁移事务中增加以下结构，并登记现有普通素材、媒体及文件：

- `asset_core`：核心 UUID、普通素材或媒体来源 ID、登记时间；外键级联与单一来源约束。
- `asset_files`：核心资产 ID、文件 ID、来源类别、已登记来源文件 ID或安全相对路径、文件名、用途、扩展名、大小、校验值、时间。物理文件的既有所有权不改变。
- `asset_metadata`：资产/文件关联、可空尺寸、时长、编码、FPS。未知值是空，不伪造为 0 或“解析成功”。
- `asset_sources`：核心资产 ID、来源类型、URL、作者、时间；与原有来源一起汇总，重复来源不反复插入。
- `asset_versions`：核心资产 ID、版本标签、已登记文件 ID、说明、创建时间。同一资产内版本标签唯一，文件必须是当前库中可访问的托管文件。
- 标签颜色与创建时间：仅增量扩展需要展示这些字段的现有标签表，缺省值保持兼容。

标签及项目关系通过现有关系表适配，不维护第二套互相不同步的成员关系。前端类型名可以是 Asset / AssetFile / AssetMetadata，但不得修改旧 AssetInput 的含义。

软删除不清理核心文件与版本。永久删除沿用现有确认、数据库与文件清理流程；若文件仍被其他资产版本引用，阻止破坏性清理并说明引用对象。删除标签仅解除所选资产的关系，不删除共享标签。

迁移可重复运行，只补充未登记记录；不进行全库 ffprobe、缩略图重建或大文件重新哈希。升级失败回滚，不留下半迁移结构。旧备份恢复后执行相同迁移。

## 5. 多文件、版本与重复引用

版本是用户明确创建的文件迭代，不根据 `final`、文件名或目录顺序猜测分组。

资产详情可查看原件、依赖、代理、缩略图及追加的托管文件。追加文件使用现有安全导入器；文件成功登记后才允许建立版本。可以命名 `v001`、`v002`、`Final`，并保存版本说明。

版本只引用指定文件，不复制相同内容。版本文件使用已有媒体协议和预览能力；切换版本不覆盖原文件、来源或已有项目关联。

相同 Hash 的文件提示“该素材已经存在”，可打开现有资产，或选择项目创建使用引用。这里的引用复用现有核心身份与文件，不建立重复物理副本或重名媒体记录。重复记录在回收站时提示先恢复，不静默恢复、复制或覆盖。

没有明确来源、项目或标签的本地文件只登记为本地导入，不推断为 YouTube、不自动关联项目、不生成“赛博朋克／夜景”等标签。任务书的示例字段仅在来源已知或用户填写时出现。

## 6. 目录扫描与安全

用户选择目录后先扫描并显示可导入、重复、不支持和失败清单；确认后提交后台导入任务。扫描不等于实时监视目录，也不自动修改源文件。

第一阶段扫描接受任务书的视频 mp4/mov/mkv/webm、图片 png/jpg/jpeg/webp、音频 mp3/wav/flac。既有媒体库支持的其他格式及模型导入继续可用；uasset/umap 为预留类型，不宣称能解析或预览 UE 格式，已有 FBX 模型能力不删除。

扫描支持子目录，跳过符号链接、junction/reparse point、托管目录、临时目录及 `.git`。每层检查取消标记，分批处理，不一次把所有文件内容读入内存。源目录不可读、文件移动、单文件损坏等作为逐文件结果，不终止其他有效文件。

导入复制原件，沿用临时文件、空间检查和原子提交；不覆盖同名文件。前端读取仍使用 UUID 和数据库登记文件，不能用扫描获得的路径绕过媒体协议。

## 7. 元数据与统一缩略图入口

新增 `media_engine/thumbnail.rs` 作为图片与音视频缩略图的统一调用入口，复用现有图片处理、FFmpeg 参数和资源工具管理，不重写第二个处理引擎。

新增资产级缩略图缓存可以使用 `.dcc/cache/thumbnails/`，旧缩略图继续原位有效，不在迁移时搬移。新缓存路径必须按资产/文件 UUID生成，受当前素材库边界约束；数据库登记后方可读取。

图片读取尺寸；音视频使用现有 ffprobe 获取尺寸、时长、编码、FPS。重试时只补缺失或明确要求重新处理的字段。解析失败保留原件并显示失败原因，不能把空元数据当作完成。

现有 3D 缩略图与 Three.js 材质预览继续使用原实现，不被音视频缩略图改动替换。

## 8. UI 与搜索

保留当前素材库导航、四媒体模块及现有样式。在素材库提供明确的“普通素材／全部资产”浏览范围：默认普通素材保留当前 Fab、分类、双语筛选和批量操作；全部资产使用统一 AssetBrowser，不把只适用于 Fab 的操作套用到视频或音频。

新增 `src/features/assets/` 的 AssetBrowser、AssetCard、AssetDetail、TagPanel、SourcePanel、VersionPanel。卡片显示缩略图、名称、类型、标签摘要、更新时间；分页或沿用既有虚拟列表，不一次加载全部记录。

详情展示基本信息、文件、元数据、标签、来源、版本、关联项目与现有知识关联。可以打开旧详情继续使用专属功能，不删除已有入口。

统一搜索支持名称、标签、类型、来源，使用参数化查询与分页。现有高级素材搜索及智能集合语义保持不变，不能因统一浏览而把旧查询条件静默丢弃。

操作沿用局部加载、失败重试、取消与空状态。该版本不重做主题、布局或全局导航，不增加大型前端依赖。

## 9. 后台任务与下载接入

在现有 TaskRequest 中接入资产目录扫描、导入、缩略图/元数据处理；任务中心继续统一展示 queued、processing、completed、failed 及取消状态。不要建立独立 ImportTask 数据库或另一套队列。

任务绑定创建时的素材库。切库不让任务结果写到新库，应用重启后由用户继续，不自动联网。错误与进度采用现有持久化机制；单个附件失败不影响其他附件。

v0.21 下载流程继续运行 yt-dlp → 校验 → ffprobe → 安全媒体入库；在成功入库边界登记统一资产、来源与元数据。保留 media_sources 和 download_tasks，不对下载文件进行第二次导入。核心登记失败时保留已下载/已入库文件，重试登记必须幂等。

## 10. 验收与实施阶段

严格按任务书次序：

1. Asset Model：新增 schema、模型与适配器，证明迁移保留旧记录、ID及关系，迁移重入不重复。
2. Scanner：目录扫描、逐文件报告、任务取消、类型边界、同 Hash 引用、不覆盖源文件。
3. Thumbnail：统一缩略图入口与元数据，验证损坏文件、工具缺失和处理失败保留数据。
4. Tag System：复用标签，验证添加、解除、搜索、双语与共享词库不被破坏。
5. Asset UI：统一浏览、详情、来源、版本、项目关联与搜索，保留旧入口和专属操作。
6. Download Integration：下载自动登记资产，来源正确、相同内容重复任务不复制文件，暂停/恢复/取消不回退。

Rust 测试覆盖迁移、外键与事务回滚、混合类型查询、目录边界、重复与回收站、版本文件所属、关联清理、来源、缩略图失败和下载幂等。React/Vitest 测试覆盖浏览范围、搜索、标签操作、来源、版本、重复引用、局部失败和旧入口保留。

最终执行完整前端测试、Rust 测试、生产构建及 Windows x64 中文 NSIS 构建。测试、构建与 Windows 实机验收分别报告，不以自动化测试代替真实站点、Epic 或干净安装验收。不自动推送、合并或发布 GitHub，除非用户另行授权。
