# DCC v0.23 Asset Intelligence Layer：兼容扩展设计

状态：用户已确认本设计；实施计划待审阅。尚未修改产品代码。

依据：用户提供的《DCC v0.23 资产智能层开发任务》。本设计保留其五个 Phase 顺序、P0/P1 功能和明确禁用项，补充当前仓库所需的兼容、安全与验收细节。

## 1. 目标、现状与边界

目标是把参考素材、Prompt、生成结果、项目和 Shot 连成可检索的创作资产网络，同时允许用户明确发起 AI 内容分析并确认标签建议。

当前应用为 v0.22.0，数据库 schema 为 21。统一资产由 `asset_core` 登记，实际普通素材和媒体数据仍分别由原表负责。现有 `asset_files`、托管协议、共享标签、项目、镜头、后台任务、DeepSeek 凭据及月度额度继续使用。

不删除或替换 Asset/AssetFile，不搬移旧原件，不重写素材库、任务系统或 AI 助手。不增加自动生成视频、剪辑、自动镜头识别、完整聊天、复杂向量数据库、UE 原生资产管理或全库后台 AI 扫描。

## 2. 实施方案选择

推荐兼容式扩展：关系与分析引用现有核心 UUID；Prompt/Shot 补充文本型资产；镜头绑定现有 `project_units`，而非再实现一套项目镜头系统。

不采用把整个媒体管理切换为 Immich/Jellyfin 服务的方案：会改变单机部署、文件所有权及备份边界。也不把现有 `assets` 表整体改名或用新模型替换它。

参考项目仅用于产品与架构思路，独立实现；不引入其 GPL/AGPL 服务端或复制相关实现代码：

- [Immich](https://github.com/immich-app/immich)：后台分析与搜索分离。
- [Jellyfin](https://github.com/jellyfin/jellyfin)：文件、元数据与处理状态分离。
- [Obsidian Graph](https://obsidian.md/help/plugins/graph)：局部关系图和关联导航。
- [Kitsu](https://github.com/cgwire/kitsu)：项目中的镜头流程。
- Eagle：沿用栈藏已有收藏与共享标签交互，不新增平行收藏体系。

## 3. Phase 1：资产关系

新增 `asset/relations.rs` 与 `src/features/intelligence/relations/GraphView.tsx`。关系 CRUD、图查询和候选资产搜索均限定当前素材库，并接受 `expectedLibraryId`。

`asset_relations` 使用核心资产外键、两个方向索引、关系类型 CHECK 和 `(source_asset_id,target_asset_id,relation_type)` 唯一约束。拒绝自关联、未知类型、不存在或已软删除的端点。永久删除资产级联清理关联；软删除保留记录并显示不可用，不偷偷恢复。

支持任务书全部七类关系。UI 必须清楚显示两端及方向，不能只显示含糊的“相关”：

- `inspired_by`：当前资产 → 灵感来源。
- `generated_from`：生成结果 → Prompt/输入来源。
- `derived_from`：衍生资产 → 原资产。
- `used_in`：素材/Prompt/结果 → 使用它的 Shot 或其他资产。
- `reference_of`：参考资产 → 被参考的目标。
- `variant_of`、`related_to`：双向关系，以 UUID 排序规范化端点，防止反向重复。

任务书示意图以创作时间顺序展示链条，数据库中的 `generated_from` 则按“结果来自输入”保存；图的箭头、中文说明和表单端点保持一致。

关系图默认围绕选中资产显示一跳关系，每页最多 80 个邻居；显示截断/总数，可翻页或点击邻居作为新的中心。不一次加载或模拟布局 10,000 个节点。SVG 连线和现有 React 组件足够，不新增图布局依赖。提供对应的可键盘操作关系列表，支持查看、打开资产、添加和删除关系。

## 4. Phase 2：AI 分析基础层

新增 `asset/analysis.rs`、`ai/analyzer.rs`。现有 `ai.rs` 可以继续作为模块根并声明子模块，不为创建目录而搬迁整个 AI 助手。

现有模型常量为 `deepseek-flash`。截至本次核对，[官方视觉接口](https://api-docs.deepseek.com/guides/vision/)支持文本与图片混合输入，因此继续使用现有 DeepSeek 凭据与请求管理，不新增供应商或保存明文密钥。

### 分析输入与明确授权

- 默认不自动分析新导入素材。用户在详情中先预览将发送的资料，再明确点击“开始分析”。
- 图片发送按需缩小的托管图像；视频用已有 FFmpeg 在固定时间点抽取最多 4 帧，不上传完整视频。保留时间点并标注“基于采样帧，不能保证覆盖完整视频”。
- 模型可分析已有渲染缩略图，明确标记为预览图分析，不声称读取模型拓扑、材质文件或工程内容。
- 没有可用画面的素材仅能选择文字资料分析，明确标记“基于名称、描述、标签及元数据”。音频不声称被听取或转写。
- 没有托管原件的 Fab 素材不会隐式下载商品文件；可用预览图片或文字资料。
- 请求不发送磁盘路径、整库内容、Cookie、API key、签名或未选中的素材。资料中的指令只是内容，不具有执行权限。

### 后台任务、结果与缓存

接入现有 `TaskRequest` / `LibraryTask`，新增 `AIAnalyze`；名称对齐现有任务序列化约定。沿用 queued/running/completed/failed/stopped/interrupted 生命周期、取消、失败重试和任务中心，阶段说明显示准备资料、请求模型、验证结果和保存。

准备图像、抽帧、校验及数据库工作使用后台 worker；网络调用异步执行。不跨网络请求持有素材库锁。取消和切库后不写入迟到结果；排队后资料改变时要求重新预览，不能分析用户未确认的新内容。

`asset_ai_analysis` 保存任务书的 description、keywords、scene、style、camera、lighting、mood、model、created_at，并补充输入摘要、输入指纹、分析模式、格式版本和实际用量。结果是独立分析资料，不覆盖用户的名称/描述。

缓存身份由核心资产 UUID、已确认输入指纹、模型、分析模式与格式版本共同决定；相同资料优先复用，不重复联网。原件、选定文字或分析版本改变时旧结果标记过期，保留供查看。主动重新分析需要明确操作。失败/空结果/非法 JSON 不写成功缓存。

继续共用现有用量预算、请求占用锁和取消逻辑。视觉输入的额度预估不能直接把 Base64 字节数当作文本 token；为经过大小限制的图像独立预估，实际用量按供应商返回值结算。CI 使用本地模拟响应，不调用真实服务或读取实际密钥。

### 标签建议

分析结果显示可勾选关键词及其来源。用户确认后只追加所选新标签，复用共享词库，保留现有标签。后端重新读取当前标签并在同一事务内合并，避免 UI 的旧快照覆盖用户后来修改的标签。长度、数量、去重和当前库校验都在后端执行。

## 5. Phase 3：搜索增强与 Embedding 预留

统一资产浏览的关键词搜索扩展至名称、用户描述、标签、AI 描述/关键词、来源 URL/作者及项目名称。类型、来源、项目与分页条件共同生效；参数化 SQL，页面最多 200 项。

“雨夜未来城市”只有在保存的用户/AI 描述或关键词包含对应内容时才能匹配。本版不把字符串搜索包装成向量语义理解，也不以 AI 自动改写每个搜索请求消耗额度。

`search/semantic.rs` 隔离未来语义搜索入口；默认返回明确的“未配置语义检索”，不静默丢弃筛选条件。

按任务书增加 `asset_embeddings` 与 `ai/embedding.rs` 的类型化接口，保存核心资产 ID、有限长度有限数值向量、模型、输入指纹、维度与时间。只预留注册/校验能力，不部署向量数据库、不下载模型、不自动生成 embedding。

## 6. Phase 4：Prompt 作为正式资产

新增 `asset/prompt.rs` 与 `PromptEditor.tsx`，支持创建、编辑、查询、复制内容、关联输入与输出，具备独立核心 UUID，并在统一资产浏览中按 `prompt` 筛选。

`prompts` 保存 asset_id、content、model、parameters、created_at/updated_at。parameters 只允许有大小限制的 JSON 对象，不接受脚本或执行参数。model 是创作记录，不会因为保存 Prompt 而调用生成模型。

输入与输出由通用关系模块表达，不重复维护第二份可冲突的资产关联数组。编辑保存有修订校验，避免打开两个详情时互相覆盖。文本型资产不强制存在本地文件或 Fab 链接，也不提供误导性的“播放/模型预览”按钮。

## 7. Phase 5：Shot 与现有项目流程

新增 `asset/shot.rs`、`workflow/shot_manager.rs` 与 `ShotPanel.tsx`。

Shot 具有核心资产身份，`shots` 扩展保存 asset_id、project_id、project_unit_id、act、shot_number、status、description、时间和修订号。绑定已有 kind=shot 的 `project_units`，沿用其父场景、帧范围、分辨率、帧率及视频引用；不重做项目看板。

ACT 是 Shot 的可编辑分组字段，不额外创建另一套场景树。状态固定为待办、进行中、待检查、完成，使用当前项目的状态词汇。镜头状态不自动批量修改它关联的全部任务状态。

支持为既有镜头登记 Shot Asset、在选定项目/场景下创建新镜头、查看引用/Prompt/输出关系。创建镜头和核心资产必须同一事务，失败回滚。

项目或镜头被删除时，保留 Shot Asset 的创作记录并解除已不存在的项目/镜头绑定；不删除它引用的素材、Prompt 或媒体。项目归档保留关系。删除 Shot Asset 也不自动删除整个项目、素材或已存在的项目镜头。

## 8. schema 22 与文本型资产身份

应用版本为 v0.23.0，schema 从 21 增量升级至 22；备份格式沿用现有机制。

当前 `asset_core` 的 CHECK 要求恰好对应一个普通素材或媒体，无法容纳没有文件的 Prompt/Shot。推荐只迁移这张小型注册表的来源约束：增加文本实体来源，保留所有既有核心 UUID、旧来源 ID 与创建时间，并以独立 `asset_entities` 保存新文本实体的名称、描述、类型、删除状态和修订信息。不能更换任何旧资产身份或重新导入旧文件。

既有 `assets`、media_entries、asset_files、版本与物理原件不重建。注册表迁移在事务中复制并验证计数、ID 与外键，失败回滚；完整恢复外键检查，旧备份也经过相同迁移。测试覆盖迁移失败注入与二次运行。

除任务书的 asset_relations、asset_ai_analysis、asset_embeddings、prompts、shots 外，仅为文本实体增加必要的共享标签/项目关联适配表；旧普通素材和媒体仍使用原有标签、项目关系，不产生双份成员数据。

Prompt/Shot 的删除沿用软删除与现有回收站批次，永久清理只清除它自身和关系记录。不新增独立媒体库或平行回收站。

## 9. UI 与可用性

沿用当前主题、组件、加载反馈和素材库入口，不大改整体 UI。

统一详情增加基础信息、文件、Metadata、标签、来源、版本、关系、AI分析、Prompt、项目标签页；不适用的标签页展示明确空状态或禁用说明。Shot 流程放在项目页/项目标签页，不凭空新增完整影视管理模块。

标签栏保持可见，可键盘切换；请求中的按钮防重复提交。图、AI分析和文本编辑按需加载；取消、失败、无原件、缓存过期和正在处理都有可辨认状态。详情外部点击/Escape 关闭继续可用，不造成编辑内容无提示丢失。

统一资产浏览提供新建 Prompt、登记 Shot 和类型筛选。旧普通素材、四个媒体库、Fab 导入/定位、翻译、参考板、知识库、下载和切库保持原入口。

## 10. 验证与交付

严格按五个 Phase：每阶段先写失败测试、实现最小闭环、验证通过，再推进下一阶段。

Rust 测试覆盖关系方向/重复/删除/越库、schema 21→22 与原件/UUID保留、AI模拟请求/取消/缓存/用量/响应校验/切库、标签追加并发、搜索字段组合、Prompt CRUD、Shot 事务及项目删除保留资产、embedding 有限数值验证。

React/Vitest 覆盖关系图导航与截断、详情标签切换、分析输入预览与明确确认、建议勾选、失败重试、Prompt 创建编辑、项目镜头登记及搜索。

使用 10,000+ 核心资产验证分页、索引检索和局部关系图；记录实际耗时与测试环境，不把测试用例通过等同于低配 Windows 实机验收。

完成全量前端/Rust回归、生产构建、中文 Windows x64 NSIS 打包，输出任务书要求的文件清单、模块、数据库/API/UI变化、测试与构建结果、已知限制及下一阶段建议。新版本 GitHub 推送/合并/Release 按用户后续发布指令执行，不绕过工具权限。
