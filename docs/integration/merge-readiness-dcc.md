### 三类存储边界

1. **属于当前素材库**：素材、媒体登记及托管文件、项目、笔记、附件、参考板、资产关系/分析。默认备份目录包括 images、media、media-library、note-attachments、reference-boards、`.dcc/cache/thumbnails`。
2. **属于本机应用**：活动库/最近库、主题与全局偏好、任务 journal、术语表、翻译缓存和额度记录、下载设置、升级备份登记。整库包不会迁移所有这些本机状态。
3. **敏感与外部数据**：Windows 凭据/DPAPI Cookie、用户外部源视频、Markdown/Vault 原文件。它们不因“合并软件”自动变成可覆盖或删除的数据。

## 主要冲突与集成约束

| 冲突 | 影响 / 处理建议（待新设计批准） |
| --- | --- |
| 结构化笔记 vs Markdown/Vault | 栈藏 JSON 文档与映流文件字节、frontmatter/Obsidian 语法、expectedHash 机制不同。不得全库转换或覆盖已有正文。建议先做显式迁入预检、附件/引用映射和无损性证明，再确定是否保留只读原文副本/文件关联。 |
| 课程与媒体的生命周期 | 一个教程可能由下载、外部路径或栈藏托管媒体提供；不同项目可复用。建议学习记录以稳定课程 ID 关联媒体 ID，项目上下文单独关联，源件变化使旧分析失效。 |
| 时间单位与来源校验 | 现有 probe duration 为秒浮点；课程字幕/播放定位拟用整数毫秒。转换只在明确边界做，保留不连续范围；不能放宽映流引用校验得到“成功”。 |
| 新旧分析结果 | v0.23 资产摘要有自己的指纹、模型和结果版本；课程全片分析需要字幕/画面出处、阶段缓存和部分完成。建议独立结果类型，共用队列/预算，禁止覆盖既有 asset_ai_analysis。 |
| 异步任务与库切换 | 当前库被维护/恢复或切换时，旧课程响应不能写入新库；长 hash/FFmpeg/网络不长期占库锁。新任务必须可取消、失败阶段续作、跨重启恢复且不自动重发付费请求。 |
| mpv 原生视口 | 当前 HTML 视频预览/3D 及参考板悬浮窗已有自己的窗口生命周期。移入 mpv 需单独处理父窗口、DPI、弹层遮挡、焦点、退出、句柄释放和资源许可。不能把源端模拟通过当成 DCC 实机通过。 |
| 模块和快捷键 | 当前 ModuleId/持久偏好/命令入口需要兼容旧值。Tab/编辑快捷键、F11、搜索/截图键要在新模块焦点内生效，不能劫持素材/笔记输入或全局替换键位。 |
| 去重与历史迁入 | 文件 hash、栈藏库/媒体 UUID、映流 Vault/课程/笔记 ID 是不同维度。需独立迁入批次及来源映射，使重试幂等并可逐项恢复，不能仅按标题或当前路径去重。 |
| 备份跨库身份 | 已验证恢复到新库保持目标 marker UUID、实体 UUID 保留；迁入映流来源身份不应假设和目标库 UUID 相等。不能复制应用配置或凭据来自动获得授权。 |
| 工具/安装体积 | yt-dlp/FFmpeg/FFprobe 已存在；播放器/转录若带新二进制，须核对版本、架构、许可证和原生依赖。保留旧安装包，最终另行授权安装/发布。 |

## 需要新合并设计裁定的迁移事项

以下是待裁定项与建议默认值，不作为已批准实施方案：

补充：随后收到的新设计草稿已选择“document_json 默认权威 + 原 Markdown 归档”和“旧视频默认引用”。下列清单保留为最初盘点记录，具体实现风险及仍待审阅项以文末复核为准。

1. **笔记长期存储**：以栈藏结构化正文为主，还是引入文件型 Vault；特殊 Markdown/Obsidian 块怎样可编辑且保真。建议先保留现有栈藏存储，避免自动整库转换。
2. **旧数据迁入范围**：课程、播放位置、字幕、分析缓存、笔记、附件、历史版本分别是否迁入；目标库/笔记本由谁选择。建议显式预检后按批次迁入，源库始终只读。
3. **原视频策略**：已有外部视频是复制托管还是安全只读关联；目标磁盘空间不足如何处理。当前媒体库默认复制，不能悄悄改成外链；建议把是否复制作为明示决策，默认不复制整段教程。
4. **旧身份/重复处理**：课程或笔记重复时复用、并存还是跳过；附件和时间码链接重映射规则。建议按来源稳定身份保留迁入映射，同标题不自动合并。
5. **AI 配置/费用**：复用哪些模型/接口，历史用量如何显示、后续如何预算。建议默认保留栈藏凭据和额度，迁入不发付费请求，敏感信息单独确认并不写入备份。
6. **学习模块位置**：媒体详情直接进入学习视图，是否有独立学习导航；与项目学习资料、知识库怎样组合。建议复用当前工作区路由/详情，不增加第二个项目或媒体中心。
7. **回滚范围**：迁入失败如何逐批回退、什么时候允许清理映流旧安装/数据。建议保留原软件和原库，阶段通过后由用户另行选择清理；旧程序不得直接写新 schema。

## 推荐的后续验证顺序

新设计批准后，先核对映流窗口提供的实际源提交与移植清单，再选择最小闭环：**栈藏登记媒体 → 本进程学习播放 → 保存本库课程进度 → 时间码摘录 → 关联现有笔记/项目 → 退出重启/备份恢复**。字幕/分析在播放器生命周期与数据归属稳定后分阶段迁入。

移植验证应区分：代码/自动测试、生成 fixture、真实映流旧库导入、DCC 原生 Windows 操作、付费服务。用户库必须先备份并预检；新数据库迁移、安装与发布均未获本准备步骤授权。

- M0 先交源快照/导出格式、ID 映射表和能力许可清单，至少包含：重复、缺失文件、特殊 Markdown、外部修改、旧历史及现有栈藏同内容媒体。
