# v0.20.2 Epic Fab 商品定位修复（测试版）

后续实机反馈确认此版仍有连续定位失效，不能作为完整验收通过版本。共享导航交接修复及验证边界见 [v0.20.3 说明](v0.20.3-epic-warm-navigation.md)。旧安装包仅保留作为历史基线。

基于 v0.20.1 `1191b8d7a2dc82ed0f5df80673c5d2de62acf68d`，继续保留 v0.20 创作流程。不恢复已取消的 UE 原生素材模块，不修改素材库 schema、登录信息或用户工程。

## 原因与修复

本机 Epic Games Launcher 20.3.4-0+UE5 的历史路由日志显示，旧 `ue/Fab/product/{UUID}` 被判为 `Invalid location`，随后退回 `/ue/library`。该历史故障共出现三次，与用户截图一致。旧单测仅锁定地址形状，不能证明 Launcher 商品页面实际打开。

固定入口改为 `com.epicgames.launcher://fab/plugins/egl/listings/{UUID}`。UUID 仍只从当前库已保存且来源一致的 Fab 素材读取；不会接受任意协议地址、安装参数或账户数据。

系统调用成功只返回 `requested: true`，表示已发送请求，不表示商品页面、下载或安装成功。用户需核对 Epic 中的商品，然后点“添加到工程”并确认工程与版本；完整工程或插件采用 Epic 对应的“创建工程”或“安装插件”。

保留显式的重试定位、复制商品名、打开官方商品页入口。复制优先使用已保存的英文名称，没有英文则使用当前名称。官方页面通过原有 Rust 安全外链命令打开，不自动跳转浏览器。工程检查、官方支持版本、切库门控、模态窗口焦点与取消保护保持不变。

## 验证边界

路由回归测试先对旧生产函数运行并失败，再修复。其输入仍经真实数据库来源校验，覆盖错误域名、来源与 ID 不一致、端口、登录信息、非法路径及已删除素材，不能仅改变前端 URI。

2026-10-07 在本机 Launcher 20.3.4 向同一公开商品请求新入口；仅提取固定商品 UUID 的路由阶段和时间，未输出原始日志、账户或凭据。日志记录了 `GoToUrl` 和 `Started processing URI`，本次未见旧式路由拒绝。**这只能证明请求已分发，不能证明 Fab WebView 正确显示商品。** 商品详情和实际“添加到工程”仍需实机视觉验收，不因自动测试通过而宣称完成安装。

测试包不自动安装或覆盖运行中的应用。原 v0.20.0 和 v0.20.1 安装包继续保留；更新现有草稿 PR，不自动合并或正式发布。

## 实机验收

1. 打开已购 Fab 素材，选择可用 `.uproject` 与 Fab 支持版本，点击“定位 Fab 商品”。
2. 确认 Epic 显示的是对应商品详情，而非 UE 库首页。在 Epic 点“添加到工程”，重新核对工程和版本后确认。
3. 若 Epic 没有显示商品，弹窗不得显示“已打开商品”或“已安装”；可重试，或复制商品名后在 Epic 的 Fab 页搜索；官方页面仅在主动点击后打开。
4. 未安装/协议损坏、剪贴板拒绝、工程失效和来源错误都有明确错误；关闭弹窗或切库后迟到响应不覆盖当前状态。
